# Отчёт: метрики, стоимость, самая слабая метрика

Прогон: 2026-11-11, модель `qwen3-14b` (LM Studio, локально), обе роли — основная и служебная —
на одной модели, различаются условные тарифы. Промпты: отпечаток `ea835a6d54`. Команда:
`make eval` (подмножество из эталона: `blender_passport.pdf`, `kettle_manual.pdf`).
Сырые данные — `evals/reports/metrics-20261111-084452.json`.

## Метрики на эталоне

| документ | характеристики | цитирование | судья | недостающие: полнота | недостающие: точность |
|---|---|---|---|---|---|
| blender_passport.pdf | 1.00 | 1.00 | 1.00 | — (ожидаемо пусто) | 1.00 |
| kettle_manual.pdf | 1.00 | **0.00** | 1.00 | 1.00 | 1.00 |
| **среднее** | **1.00** | **0.50** | **1.00** | 1.00 | 1.00 |

- *Характеристики* — доля ожидаемых из `golden_cards.json`, совпавших с карточкой после
  нормализации значений («800 Вт» = «800 вт» = «800 Вт.», «1,5» = «1.5», «1 490» = «1490»).
- *Цитирование* — доля карточек, где каждая ссылка ведёт на фрагмент, который действительно
  содержит значение (страница берётся из базы по `chunk_id`).
- *Судья* — модель называет характеристики, которые источники не подтверждают; долю считает код.
  Это оценка, а не истина.

Метрики считаются за одну попытку, без переделок: это замер самого генератора. В рабочем
процессе ссылки проверяются кодом и при нарушении карточка переделывается.

## Стоимость одной карточки

Цены условные (₽ за 1 млн токенов: основная 15 вх. / 60 исх., служебная 3 / 12): локальная
модель бесплатна, тарифы нужны, чтобы видеть разницу. Стоимость задачи считается одним запросом:
`GET /jobs/{id}/cost`, `make costs JOB=<id>` или `SELECT … FROM llm_calls WHERE job_id = …`.

| карточка | вызовов модели | токенов вх. / исх. | стоимость, ₽ | время в модели |
|---|---|---|---|---|
| blender_passport.pdf (метрики) | 3 | — / — (7 402 всего) | 0.2117 | 115 с |
| kettle_manual.pdf (метрики) | 3 | — / — (8 098 всего) | 0.2421 | 127 с |
| blender_passport.pdf (процесс: поиск → карточка → проверка) | 3 | 5 905 / 4 982 | 0.3166 | 150 с |
| kettle_manual.pdf с инъекцией (процесс, +детектор, +переделка) | 4 | 4 199 / 4 465 | 0.3065 | 131 с |

**Типичная карточка — 0.2–0.3 ₽ и 2–2.5 минуты на локальной модели.** Основная часть стоимости —
генерация (извлечение фактов и сборка карточки, основной тариф); служебные роли (проверяющая,
судья, детектор инъекций) дешевле в 5 раз и занимают 6–15 % суммы. Обращения детектора
инъекций видны в `llm_calls` отдельной строкой (`InjectionDetector`, тариф `light`): около
0.006 ₽ за обращение — безопасность стоит сотые доли карточки.

## Самая слабая метрика — цитирование (0.50)

У `kettle_manual.pdf` 10 ссылок из 13 верны; три неверные относятся к характеристикам, которых
нет в таблице документа: модель вынесла их из прозы и **пересказала** («двойная стенка (металл
снаружи, термостойкий пластик внутри)», «откидная с блокировкой», «закрытая из нержавеющей
стали»). Такого значения нет дословно ни в одном фрагменте, поэтому ссылка «значение лежит в
указанном фрагменте» не подтверждается.

Почему именно эта метрика слабее остальных:

1. **Она самая строгая по построению.** «Характеристики» сверяют только ключи эталона:
   лишние пересказы модели им не мешают. «Цитирование» проверяет каждую заявленную ссылку и
   требует, чтобы значение нашлось в указанном фрагменте.
2. **Судья её не видит (1.00 на обоих документах).** Он получает все фрагменты разом и признаёт
   пересказ верным по смыслу; к тому же судит та же модель, что и пишет, — она мягка к себе.
   Метрика цитирования ловит то, что пропускает судья: «верно по смыслу, но взято не оттуда».
3. **Причина в генераторе, а не в данных:** модель смешивает два вида характеристик — строки
   таблицы и выжимку из описательного текста — и для второго вида пересказывает.

Что с этим делать (и теперь это можно измерить, отпечаток промптов в отчёте фиксирует «до»):
потребовать в промпте дословные значения, а пересказы из прозы класть в описание, а не в
характеристики; либо смягчить сравнение значений (нормализация синонимов). В рабочем процессе
эта слабость уже закрыта вторым рубежом: ссылка без значения в источнике переделывается.

## Как воспроизвести

```bash
uv run python scripts/demo.py     # карточки по всем выданным документам, включая инъекцию и скан
make eval                         # метрики на подмножестве; make eval ALL=1 — весь набор
make costs                        # разбивка по моделям и тарифам; make costs JOB=<id>
```
